## Методика измерений

- таймер `time.perf_counter()`; один и тот же массив (`seed = 42`) подаётся всем алгоритмам, сортируется его копия;

## Выводы

1. Время работы всех трёх алгоритмов растёт квадратично. Отношение T(n)/n² почти постоянно: 17,5–20,0·10⁻⁹ с у пузырька, 2,9–3,8·10⁻⁹ с у шейкерной сортировки и 1,4–1,8·10⁻⁹ с у вставок. При удвоении n время возрастает в 3,5–4,5 (пузырёк), 3,1–5,0 (шейкер) и 3,1–4,6 раза (вставки) при теоретическом значении 4. Отклонения вызваны линейными накладными расходами цикла, кэш-памятью процессора и случайными помехами при замере.
2. «Почти упорядоченные» данные (n/20 случайных перестановок пар) не дают линейного времени. Переставляемые элементы находятся в среднем на расстоянии около n/3 друг от друга, поэтому число инверсий (оно же число обменов, табл. 7) составляет около 0,030·n². Это примерно в 8 раз меньше, чем у случайного массива (≈ n²/4), но всё равно квадратично зависит от n. Поэтому сортировка вставками остаётся Θ(n²), только с малым множителем.
3. Сортировка пузырьком выполняет 0,80–0,99·n проходов, то есть почти столько же, сколько в худшем случае. Причина: элемент, оказавшийся правее своего места, смещается влево лишь на одну позицию за проход. Поэтому флаг досрочного выхода почти не помогает, число сравнений составляет 96–100 % от n²/2 (табл. 6). Из-за этого пузырёк в 11–13 раз медленнее вставок.
4. Шейкерная сортировка (М5) работает в 5,2–6,4 раза быстрее обычного пузырька. Обратный проход возвращает влево «лёгкие» элементы, попавшие вправо, гораздо быстрее, поэтому проходов требуется только около 0,05·n (порядка числа переставленных пар, n/20), а сравнений — в 9,3–11,0 раза меньше. Выигрыш по времени меньше, чем по сравнениям, потому что число обменов у всех трёх алгоритмов одинаково (оно равно числу инверсий), а обмен дороже сравнения.
5. Сортировка вставками остаётся самой быстрой из трёх: она в 2,0–2,2 раза быстрее шейкерной. Она делает меньше сравнений (1,6–1,7 раза меньше, чем шейкерная), а сдвиг (одно присваивание) дешевле обмена двух элементов. Для данных, близких к упорядоченным, это лучший из рассмотренных алгоритмов.
6. Все три алгоритма применимы лишь для небольших массивов. Экстраполяция по T ≈ c·n² даёт для n = 100 000: пузырёк — около 3 мин, шейкерная — около 32 с, вставки — около 15 с. Для больших объёмов нужны алгоритмы со сложностью O(n log n) (ЛР № 3).

## Ответы на контрольные вопросы

**1. Сформулируйте задачу сортировки. Приведите три примера её применения в бизнес-информатике.**
Дана последовательность a₁, …, aₙ с отношением порядка ≤; нужно найти перестановку a′₁, …, a′ₙ, для которой a′₁ ≤ a′₂ ≤ … ≤ a′ₙ. Примеры: ранжирование клиентов по выручке, упорядочение транзакций по времени, подготовка данных для бинарного поиска.

**2. Дайте определения обозначений O, Ω, Θ. Чем они отличаются?**
T(n) = O(g(n)): существуют c > 0 и n₀, такие что T(n) ≤ c·g(n) при n ≥ n₀ (оценка сверху). T(n) = Ω(g(n)): T(n) ≥ c·g(n) при n ≥ n₀ (оценка снизу). T(n) = Θ(g(n)): одновременно O и Ω (точная оценка).

**3. Что такое лучший, средний и худший случаи? Какие данные худшие для сортировки вставками?**
Это время работы на самых «удачных», типичных и самых «неудачных» входах размера n. Для вставок худший случай — массив, упорядоченный по убыванию: каждый элемент сдвигается через весь отсортированный префикс (≈ n²/2 сдвигов).

**4. Как флаг `swapped` влияет на сложность пузырька в лучшем случае?**
С флагом на упорядоченном массиве достаточно одного прохода (n − 1 сравнение), то есть Θ(n). Без флага алгоритм всегда делает ≈ n²/2 сравнений, то есть Θ(n²). Но на наших данных флаг почти не помог: проходов 0,80–0,99·n (табл. 8).

**5. Что такое инверсия? Как число инверсий связано с трудоёмкостью сортировки вставками?**
Инверсия — пара (i, j), i < j, с A[i] > A[j]. Число сдвигов в сортировке вставками равно числу инверсий I, а общее время — Θ(n + I). В наших данных I ≈ 0,030·n² (табл. 7).

**6. Что означает устойчивость сортировки? Приведите пример, когда она важна.**
Сортировка устойчива, если элементы с равными ключами сохраняют взаимный порядок. Пример: заказы, уже упорядоченные по дате, сортируются по сумме; при устойчивой сортировке заказы с одинаковой суммой останутся упорядоченными по дате.

**7. Почему для замера времени используется `perf_counter()`, а не `time()`?**
`perf_counter()` — монотонный таймер с наибольшим доступным разрешением, он не зависит от системных часов. `time()` показывает системное время, которое может быть скорректировано (например, синхронизацией по сети), и на некоторых системах имеет низкое разрешение.

**8. Почему в качестве результата берётся медиана, а не среднее арифметическое?**
Медиана устойчива к редким выбросам (фоновые процессы ОС, сборка мусора), а среднее арифметическое сильно смещается даже одним аномально большим замером.

**9. Почему при одинаковой асимптотике алгоритмы работают с разной скоростью?**
Асимптотика скрывает постоянный множитель. На наших данных все три алгоритма Θ(n²), но при n = 6000 пузырёк делает 17 890 970 сравнений, шейкерная — 1 669 245, вставки — 1 056 970; к тому же обмен двух элементов дороже сдвига одного. Время отличается в 13 раз.

**10. Оцените, сколько времени потребуется вашей реализации для сортировки 1 млн элементов.**
По формуле T ≈ c·n² (c — среднее значение T(n)/n² из табл. 4) на почти упорядоченных данных: пузырёк — около 5,1 ч, шейкерная — около 53 мин, вставки — около 25 мин. На практике время будет другим из-за кэша и памяти, но порядок величины показывает, что квадратичные алгоритмы для таких объёмов непригодны.
